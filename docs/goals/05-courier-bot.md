# Цель 05. Бот доставщиков Zumda

**Статус:** ✅ (PR #16) · **ROADMAP:** M6 (часть 1) · **Зависит от:** - (в продакшен: после цели 01)

## Зачем
Доставка района: второй продукт Zumda с первых версий. Его фундамент: один человек с одним
профилем, который возит для нескольких точек и получает все заказы в одном боте. Сейчас доставщик:
это строка в таблице одного магазина, и карточки приходят ему из бота каждого магазина отдельно.

## Что нужно от владельца
- Создать бота доставщиков в @BotFather (например, «Zumda Kuryer») и добавить его токен в GitHub
  secrets (`COURIER_BOT_TOKEN`). Токен в чат не присылать.

## Как сделано
1. **Модель** (`packages/core`):
   - `CourierProfile`: человек, один на `telegram_id`: имя, телефон, транспорт, смена до
     полуночи по местному времени (`domain/entities/courier-profile.ts`);
   - `Courier`: связь человека с одной точкой: статус `pending → active → removed`, дни работы,
     «сегодня не работает» (`domain/entities/courier.ts`). Строка `couriers` осталась связью, её
     id не меняется, поэтому `orders.courier_id`, `cash_courier_id` и `cash_handovers` работают
     как раньше;
   - назначить заказ можно, только если доставщик подтверждён, сегодня его день, он не выключен
     на сегодня и на смене: иначе `COURIER_NOT_AVAILABLE` с причиной;
   - use cases: `JoinAsCourier`, `ReviewCourier`, `SetCourierSchedule`, `SetShift`,
     `UpdateCourierProfile`, `GetCourierHome`, `CourierAdvanceOrder`; касса: по каждой точке.
2. **Миграция** `0003_courier_profiles.sql`, только добавления: таблица `courier_profiles`,
   в `couriers`: `status`, `work_days`, `off_until`; перенос нынешних доставщиков (удалённые →
   `removed`). Старые колонки `name`, `phone`, `is_active` продолжают записываться, так что
   прежний Worker работает на новой схеме. Перенос проверяет тест.
3. **Worker:**
   - секреты `COURIER_BOT_TOKEN`, `COURIER_WEBHOOK_SECRET`; вебхук `/tg/courier`
     (`src/routes/courier-bot.ts`); деплой подключает вебхук и кнопку меню `?mode=courier`;
   - приглашение `t.me/<courier_bot>?start=c_<code>` → доставщик «ждёт подтверждения», бот
     просит телефон; владелец получает «Подтвердить / Отклонить» от бота магазина;
   - карточки и пинги: из бота доставщиков с названием точки;
   - `X-Bot: courier` → initData проверяется токеном бота доставщиков, роль `courier` без
     магазина; маршруты `GET /api/courier/home`, `PUT /shift`, `PATCH /profile`,
     `PATCH /orders/:id`; владельцу: `PATCH /owner/couriers/:id`, `POST …/review`.
4. **Приложение:** экран доставщика, смена, заказы всех точек, «На руках» по каждой точке,
   транспорт; «Мой магазин → Доставщики»: «Ждут подтверждения», дни недели, «Сегодня не
   работает», «На смене»; в выборе доставщика недоступные серые с причиной.
5. **e2e:** фейковый Telegram знает бота доставщиков; сценарии `courier.spec.ts` (две точки,
   подтверждение, дни, смена, касса раздельно), `owner.spec.ts`, `money.spec.ts`.

## Definition of done
- [x] Один человек: один профиль; он работает для 2+ точек и видит их заказы в одном боте.
- [x] Пригласить может только бизнес; без принятия приглашения доставщик не появляется.
- [x] Бизнес включает и выключает доставщика по дням; доставщик отмечает «на смене»;
      назначить можно только того, кто работает сегодня и на смене.
- [x] Наличные считаются по каждой точке отдельно; точка не видит другие точки своего
      доставщика.
- [x] Нынешние доставщики перенесены миграцией без потери заказов и кассы (тест на перенос).
- [x] Бот доставщиков подключается деплоем автоматически.
- [x] Гейты зелёные, e2e с двумя точками зелёный 3 раза подряд.
- [x] `CLAUDE.md`, инструкция владельцу, CHANGELOG и ROADMAP обновлены.
- [x] PR слит.
