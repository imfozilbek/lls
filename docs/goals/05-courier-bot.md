# Цель 05. Бот доставщиков LLS

**Статус:** ⏳ · **ROADMAP:** M6 (часть 1) · **Зависит от:** — (в продакшен — после цели 01)

## Зачем
Доставка района — второй продукт LLS с первых версий. Его фундамент — один человек с одним
профилем, который возит для нескольких точек и получает все заказы в одном боте. Сейчас доставщик —
это строка в таблице одного магазина, и карточки приходят ему из бота каждого магазина отдельно.

## Что нужно от владельца
- Создать бота доставщиков в @BotFather (например, «LLS Kuryer») и добавить его токен в GitHub
  secrets (`COURIER_BOT_TOKEN`). Токен в чат не присылать.

## Что сделать
1. **Модель** (`packages/core`):
   - **`Courier` становится глобальным:** один на `telegram_id` (имя, телефон, транспорт).
     Нужна новая сущность связи `CourierBusiness` (`courier_id`, `business_id`, статус
     `invited | active | removed`, дни работы как у часов, `on_shift` — смена доставщика).
   - **Где менять:** `domain/entities/courier.ts`, `application/ports/courier-repository.ts`,
     `use-cases/courier/courier.use-cases.ts`, `dtos/courier.dto.ts`.
   - **Правила:**
     - пригласить может только бизнес;
     - доставщик принимает приглашение сам;
     - бизнес включает и выключает его по дням;
     - назначить заказ можно только активному доставщику, который сегодня работает и на смене;
     - бизнес не видит других бизнесов своего доставщика.
   - **Касса** (`money.use-cases.ts`, `cashCollectedByCourier`) остаётся по каждому бизнесу:
     проверить, что суммы разных бизнесов не смешиваются.
2. **Миграция без поломки данных** — `0004_couriers_global.sql`, только добавления:
   - новые таблицы `courier_profiles` и `courier_businesses`;
   - перенос нынешних строк `couriers` в новые таблицы (`INSERT … SELECT`);
   - старая таблица остаётся до следующего релиза (правило «два релиза»);
   - `orders.courier_id` и `cash_handovers.courier_id` продолжают работать: id связи сохраняется
     или рядом хранится соответствие — выбрать в плане цели.
3. **Worker:**
   - секрет `COURIER_BOT_TOKEN`, вебхук `/tg/courier` (секрет вебхука — как у бота LLS),
     подключение в джобе `deploy` в `.github/workflows/ci.yml`;
   - приглашение: `t.me/<courier_bot>?start=c_<code>` из «Мой магазин». `/start` в боте
     доставщиков создаёт профиль (телефон — через «поделиться контактом») и связь;
   - карточки заказов (`src/telegram/notifier.ts`) уходят доставщику **из бота доставщиков** с
     названием точки в заголовке; кнопки «Забрал» и «Доставил × как заплатили» работают как
     сейчас;
   - Mini App доставщика открывается из бота доставщиков: initData проверяется токеном бота
     доставщиков (`src/auth.ts`, новая роль-контекст `courier` без `X-Shop`), заказы — сразу всех
     его точек;
   - тесты: `test/couriers.test.ts` переписать под новую модель, плюс перенос данных миграцией.
4. **Приложение:**
   - «Мой магазин → Доставщики» (`owner/CouriersSection.tsx`): приглашение, список, дни работы
     (как в `owner/HoursEditor.tsx`), «сегодня не работает», удаление;
   - экран доставщика (`courier/CourierApp.tsx`): заказы всех точек с названием точки,
     переключатель «Я на смене», «На руках» по каждой точке отдельно.
5. **e2e** (`packages/e2e`):
   - фейковый Telegram стенда знает бота доставщиков;
   - сценарий: две точки приглашают одного человека → он принимает обе → заказы обеих точек
     в одном месте → касса раздельно → выключение по дням скрывает его из назначения.
6. **Документы:** `CLAUDE.md` (модель Courier, раздел Telegram «Courier invite», роли),
   `docs/owner-guide.md` (uz + ru), CHANGELOG, ROADMAP M6.

## Definition of done
- [ ] Один человек — один профиль; он работает для 2+ точек и видит их заказы в одном боте.
- [ ] Пригласить может только бизнес; без принятия приглашения доставщик не появляется.
- [ ] Бизнес включает и выключает доставщика по дням; доставщик отмечает «на смене»;
      назначить можно только того, кто работает сегодня и на смене.
- [ ] Наличные считаются по каждой точке отдельно; точка не видит другие точки своего
      доставщика.
- [ ] Нынешние доставщики перенесены миграцией без потери заказов и кассы (тест на перенос).
- [ ] Бот доставщиков подключается деплоем автоматически.
- [ ] Гейты зелёные, e2e с двумя точками зелёный 3 раза подряд.
- [ ] `CLAUDE.md`, инструкция владельцу, CHANGELOG и ROADMAP обновлены; PR слит.

## Чего не делаем
- Сеть района и заказы чужих точек — это цель 06.
- Автоматическую раздачу заказов.
