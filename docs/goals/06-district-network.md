# Цель 06. Сеть доставщиков района

**Статус:** 🔨 сделано с временным правилом о плате за доставку; ждёт слияния PR и решения
владельца (цель 02) · **ROADMAP:** M6 (часть 2) · **Зависит от:** 05 (бот доставщиков), 02 (плата за доставку)

## Зачем
У большинства маленьких точек своих доставщиков нет: продавец один и уйти с точки не может.
Сеть района делает онлайн-точкой **любую** точку: её заказ везёт свободный доставщик района.
Это ключевая часть видения и главная защита LLS — сеть доставщиков района нельзя быстро
скопировать.

## Что нужно от владельца
- Решение из цели 02: кто получает плату за доставку, когда везёт доставщик сети, и берёт ли
  LLS долю.
- Граница района. Предложение — радиус от центра района, например 20–30 км вокруг Гулистана; точные
  координаты и радиус задаёт владелец.

## Что сделать
1. **Ядро:**
   - **Согласие на сеть:** у профиля доставщика флаг `in_network`, который ставит только сам
     доставщик. Предложение вступить приходит каждому подключённому доставщику один раз.
   - **Район:** сущность `District` (центр + радиус). Точка принадлежит району по своей локации
     (`Business.location`).
   - **Заказ точки без своего доставщика на смене** получает признак «нужен доставщик сети».
     Его видят свободные доставщики сети района (`in_network`, на смене, без активного заказа
     сети). **Первый, кто нажал «Беру», получает заказ.** Двойной захват исключён: проверка
     в одном `db.batch` с условием, как у назначения.
   - **Деньги:**
     - деньги за товар доставщик сети сдаёт **этой точке**: касса по точке, как в цели 05;
     - плата за доставку — по решению владельца, снимком в заказе (кому и сколько);
     - расчёты и выплаты между бизнесами через LLS запрещены — фиксируем только, кто кому
       должен отдать наличные.
   - **Права:** точка видит имя и телефон доставщика сети только на своих заказах. Доставщик
     видит адрес клиента только после того, как взял заказ.
   - **Тесты:** захват одним доставщиком, гонка двух нажатий, выход из сети, касса по точке.
2. **Worker:**
   - миграция `0005_district_network.sql` (только добавления): районы, `in_network`,
     поля заказа «нужен доставщик сети» и снимок платы за доставку, индексы под поиск свободных
     доставщиков;
   - **уведомления в боте доставщиков:** «Новый заказ рядом: точка, район, сумма, расстояние» с
     кнопкой «Беру». После захвата у остальных карточка меняется на «Уже взяли». Без опроса чаще
     15 секунд;
   - **точке:** «Заказ #N везёт доставщик сети: имя»;
   - **если долго никто не берёт** (время задаёт админ), точке и админу приходит оповещение.
     Без cron: проверка при следующем событии района или по команде админа;
   - **админ в боте LLS:** `/district` — создать или изменить район, `/network` — сколько
     доставщиков в сети и на смене.
3. **Приложение:**
   - экран доставщика: переключатель «Беру заказы района», список доступных заказов района,
     «Беру»;
   - владелец, «Мой магазин → Доставщики»: переключатель «Если мои заняты, отдавать заказы сети
     района»;
   - заказ показывает, кто везёт — свой или доставщик сети.
4. **e2e:** точка без доставщиков → заказ → два доставщика сети видят его → первый берёт →
   второй видит «Уже взяли» → доставка → деньги в кассе этой точки → доставщик сдаёт их точке.
5. **Документы:** `CLAUDE.md` (District delivery: «plan» → описание как есть), инструкция
   владельцу и отдельная короткая инструкция для доставщика (uz + ru), CHANGELOG, ROADMAP M6.

## Как сделано (октябрь 2026)
Решения владельца на старте:
- плата за доставку сетью **временно остаётся у точки**, LLS долю не берёт. Это снимок в заказе
  (`delivery_fee_to`), правило — одна константа `NETWORK_DELIVERY_FEE_RECIPIENT` в ядре;
- отдавать заказы сети — **включено по умолчанию** у каждой точки;
- «никто не взял» — через **10 минут**, админ меняет для района.

Что есть:
- **Ядро:** `District`, `Business.districtId/networkDelivery`, согласие `CourierProfile.inNetwork`,
  связь `Courier` со статусом `network`. Заказ: `requestNetwork`, `claimByNetwork`, снимок платы.
  Use cases в `use-cases/network/network.use-cases.ts`: район, авто- и ручная передача, список
  «рядом» без клиента, «Беру», просрочка, сводка для админа.
- **Worker:**
  - миграция `0004_district_network.sql`;
  - «Беру» — один условный `UPDATE`;
  - бот доставщиков: предложение сети один раз, «Новый заказ рядом», «Уже взяли»;
  - бот LLS: `/district`, `/network`;
  - маршруты: `PUT /api/owner/orders/:id/network`, `PUT /api/courier/network`,
    `GET /api/courier/network/orders`, `POST …/claim`.
- **Приложение:** у доставщика «Беру заказы района» и «Заказы рядом»; у владельца «Сеть
  района», «Доставщик сети района» в выборе, «Ищем…» и «сеть района» в заказе.
- **e2e:** `specs/network.spec.ts`. Метрика «доля сетью» — в `/network`.

## Definition of done
- [x] Доставщик вступает в сеть только по своему согласию и может выйти.
- [x] Заказ точки без своего доставщика на смене видят свободные доставщики сети района;
      первый, кто нажал «Беру», получает заказ; гонка покрыта тестом.
- [x] Наличные за товар учитываются по точке.
- [ ] Плата за доставку — по решению владельца, снимком в заказе. Снимок есть; решения нет,
      временно плата у точки (цель 02).
- [x] Если никто не берёт заказ, точка и админ получают оповещение.
- [x] Точка не видит чужие точки и чужие деньги своего доставщика.
- [x] Гейты зелёные, e2e сети зелёный 3 раза подряд.
- [x] Метрика «доля заказов, доставленных сетью» считается (её покажет цель 11).
- [x] Документы обновлены.
- [ ] PR слит.

## Чего не делаем
- Алгоритм, который сам раздаёт заказы: доставщики берут сами.
- Маршруты и несколько точек за одну поездку — это этап 3 (цель 13).
- Выплаты через LLS.
