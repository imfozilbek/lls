# Цель 04. Сервисный сбор

**Статус:** ⏳ · **ROADMAP:** M8 · **Зависит от:** 02 (ставка и база сбора)

## Зачем
Это главный доход LLS: небольшой процент с каждого заказа через LLS, в любом канале. Платит
клиент отдельной строкой. Цены магазина не меняются. Доход растёт вместе с оборотом района
(`CLAUDE.md` → «Money rules»).

## Что нужно от владельца
- Ставка для пилотов и база сбора (цель 02).
- Способ, которым LLS принимает деньги от магазинов, выбранный с бухгалтером (цель 02).
- Карта LLS, на которую магазины переводят сборы. Номер хранится как настройка платформы, не в
  коде.

## Что сделать
1. **Ядро** (`packages/core`):
   - **Value object `ServiceFee`:**
     - ставка в bps (0 разрешён);
     - расчёт суммы от базы с округлением до целого сума;
     - база по решению владельца — `subtotal` или `subtotal + deliveryFee`, залог не входит никогда.
   - **`Business`:** ставка сбора (`serviceFeeBps`, по умолчанию 0), метод `setServiceFee`.
   - **`Order`:** снимок сбора (ставка + сумма), фиксируется при оформлении в
     `place-order.use-case.ts`. `total` включает сбор: клиент переводит на карту магазина
     уже новый `total` (оплата только переводом, до готовки).
   - **Отчёт:**
     - в `MoneyTotals` (`ports/order-repository.ts`) добавить `serviceFees` — сборы
       доставленных заказов за период;
     - месячный отчёт «к оплате LLS»: сборы плюс комиссия витрины.
   - **Баланс магазина перед LLS:**
     - сущность `LlsPayment` (магазин, сумма, дата, кто отметил);
     - use cases «начислено − получено = долг», `RecordLlsPayment`, `GetShopBalance`.
   - **Пауза за неуплату:** статус бизнеса или флаг `paused` с причиной; на паузе заказы
     отклоняются правилом `SHOP_PAUSED` (422).
   - **Тесты:** расчёт и округление, 0 при ставке 0, залог не входит в базу, снимок не меняется
     после смены ставки, баланс, пауза.
2. **Worker** (`packages/worker`):
   - миграция `NNNN_service_fee.sql` (следующий свободный номер; `0003` занят целью 05), только добавления: колонки в `businesses` и `orders`,
     таблица `lls_payments` с индексом `(business_id, at)`;
   - **бот LLS, команды админа** (рядом с `/market` в `src/routes/webhook.routes.ts`):
     - `/fee <slug> <percent>` — ставка;
     - `/paid <slug> <sum>` — магазин заплатил LLS;
     - `/balance <slug>` — баланс;
     - `/pause <slug>` и `/resume <slug>`;
   - **напоминание магазину** в начале месяца: сумма и карта LLS. Без cron: отправлять при
     первом действии админа `/bills` («разослать счета»). Если понадобится расписание, добавить
     `scheduled()` по правилу «No cron».
   - **тексты uz/ru:** строка «Сервис» в карточках заказа (`src/telegram/format.ts`,
     `texts.ts`) и в CSV (`src/http/csv.ts`);
   - **тесты:** `test/money.test.ts` и новый `test/service-fee.test.ts`.
3. **Приложение** (`packages/app`):
   - строка «Сервис» в корзине, оформлении и экране заказа: `CartScreen`, `CheckoutScreen`,
     `OrderScreen`. Сумму считает сервер, приложение только показывает;
   - во вкладке «Деньги» (`owner/MoneyTab.tsx`) — строка «Сервис LLS» и блок «К оплате LLS
     за месяц» с картой LLS;
   - тексты uz/ru.
4. **e2e:** ставка 0 → строки нет; ставка 1% → строка в корзине, заказе, карточке и CSV;
   `/paid` уменьшает долг; `/pause` → заказ отклонён с понятным текстом.
5. **Документы:** `docs/owner-guide.md` (uz + ru) — как устроен сбор и как платить LLS;
   CHANGELOG, ROADMAP M8.

## Definition of done
- [ ] Ставка задаётся `/fee`, по умолчанию 0; при 0 клиент нигде не видит строку сбора.
- [ ] Сумма сбора считается на сервере, хранится снимком в заказе и не меняется после смены
      ставки.
- [ ] Строка «Сервис» видна в корзине, оформлении, заказе, сообщениях бота и CSV.
- [ ] «Деньги»: сборы за период и блок «К оплате LLS за месяц».
- [ ] Баланс магазина перед LLS: `/paid` и `/balance` работают, история хранится.
- [ ] Пауза: `/pause` останавливает приём заказов, `/resume` возвращает.
- [ ] Гейты зелёные; тесты ядра покрывают сбор ≥ 90%; новые e2e зелёные 3 раза подряд.
- [ ] Бюджет JS клиента ≤ 100 КБ gzip.
- [ ] Инструкция владельцу, CHANGELOG и ROADMAP (M8) обновлены; PR слит.

## Чего не делаем
- Платёжные системы (Click, Payme).
- Автосписание: магазин платит LLS сам, по отчёту.
- Сбор с залога за бутыли.

## Открытые решения

- Нужен ли автоматический ежемесячный счёт по расписанию, решаем после первого месяца.
