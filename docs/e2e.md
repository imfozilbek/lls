# Стенд и сквозные проверки (e2e)

Стенд поднимает всю систему на одном компьютере. Mini App в настоящем браузере проходит
все пути каждого пользователя. Ни Telegram, ни Cloudflare для этого не нужны.

## Что внутри

| Часть | Где | Что делает |
|---|---|---|
| База | `packages/e2e/.state` (локальная D1) | Три демо-магазина: еда, вода, продукты. Пересоздаётся при каждом запуске |
| Worker | `wrangler dev`, порт 8787 | Настоящий код API и ботов |
| Mini App | `vite`, порт 5173 | Настоящий код приложения |
| Telegram | `packages/e2e/stand/fake-telegram.ts`, порт 8081 | Фейковый Bot API: записывает, что написал каждый бот, умеет «ломаться» |
| Заглушка WebApp | `packages/e2e/support/webapp.ts` | Подписывает initData, как Telegram, отправляет контакт боту, отдаёт геолокацию |

Worker ходит в фейковый Telegram через переменную `TELEGRAM_API_BASE`. Она задаётся только
стендом. Worker принимает в ней лишь `http://localhost` / `127.0.0.1`, иначе остаётся
`api.telegram.org`. Так токены ботов не уйдут на чужой адрес даже по ошибке.

## Команды

```bash
bun install
bun run stand          # поднять стенд и оставить работать (Ctrl+C — остановить)
bun run e2e            # прогнать все сценарии (сам поднимет стенд, если он не запущен)
```

Пока идёт e2e, не запускайте `bun run build`: сборка `@lls/core` перезапускает Worker стенда
посреди сценариев, и они падают без вины кода.

Посмотреть руками: откройте `http://localhost:5173/?shop=osh-markaz-dev` в браузере.
Вне Telegram приложение покажет «Откройте в Telegram», это правильно. Для ручного входа
используйте `bun run --cwd packages/worker init-data:dev` (см. `seed-dev.ts`).

Отчёт последнего прогона: `packages/e2e/report/index.html`. Скриншоты экранов (360 px,
светлая и тёмная тема): `packages/e2e/screenshots/`.

## Что проверяется

| Файл | Кто | Пути |
|---|---|---|
| `customer-shop.spec.ts` | Клиент магазина | `/start` → витрина → разделы → корзина (минимум, бесплатная доставка) → номер из Telegram → адрес, ориентир, геолокация → заказ → карточка владельцу → статусы → отмена → история → повтор → язык. Вода: бутыли и залог. Продукты: весовые товары |
| `customer-edges.spec.ts` | Клиент | Отказ дать номер или геолокацию, чужой контакт, пауза, нерабочие часы, стоп-лист, товар закончился в корзине и при оформлении, узбекский язык, вне Telegram, чужой бот, неверная ссылка |
| `owner.spec.ts` | Владелец | «Мой магазин» только у владельца; все статусы из приложения и из чата; отмена с причиной; чужие и старые кнопки; каталог с фото; стоп-лист; нативная кнопка Telegram; «Деньги»; настройки; логотип; приём заказов; доставщики: приглашение, вход, удаление; залог воды |
| `money.spec.ts` | Клиент, доставщик, владелец | Перевод на карту: номер и копирование, «Ждём перевод», «Деньги пришли», сообщение клиенту; наличные у доставщика и «Принял деньги»; три кнопки «Доставил» в боте; долг; возврат отменённого оплаченного; отчёт за день сходится до сума; CSV в чат; QR-плакат PNG читается; часы по дням |
| `courier.spec.ts` | Доставщик | Карточка заказа, «готов», «Забрал» в чате, «Доставил» в приложении с выбором оплаты, «На руках», имя без телефона для клиента, чужие заказы и шаги кухни закрыты, смена доставщика |
| `showcase.spec.ts` | Клиент витрины, админ | Бот LLS, поиск латиницей и кириллицей, разделы, магазин внутри бота LLS, заказ с комиссией, сообщения от бота LLS, `/market`, ограничение частоты поиска |
| `onboarding-admin.spec.ts` | Новый владелец, админ | Мастер из 3 шагов, неверный токен, заявка, ожидающий магазин, повторный бот, одобрение (webhook и кнопка меню), отказ, `/reconnect`, оповещения админу |
| `security.spec.ts` | Злоумышленник | Подпись, устаревший initData, подмена канала, чужие заказы, цены с клиента, товар другого магазина, секрет webhook, CORS, токены не утекают |
| `visual.spec.ts` | Все | Каждый главный экран на 360 px в двух темах, без горизонтальной прокрутки, скриншоты |

## В CI

Работа `e2e` в `.github/workflows/ci.yml` запускается на каждый push и pull request.
Секретов в ней нет: база локальная, все токены фейковые. Деплой ждёт и `quality-gates`, и `e2e`.
